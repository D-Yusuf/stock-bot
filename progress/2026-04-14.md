## Bugs Encountered & Fixed

### 1. session_qty recorded as 18 instead of 1
**Problem:** After buying 1 NVDA, `session_trades["NVDA"]["qty"]` was showing 18 (total held) instead of 1 (just bought).
**Fix:** Corrected the qty recorded in `record_session_trade()` to use the actual fill qty from the order, not the total position size.

### 2. SL/TP orders sized to 18sh instead of 1sh
**Problem:** Because session_qty was wrong, the protection orders (STP + LMT) were placed for 18 shares instead of 1.
**Fix:** Tied to the session_qty fix above. Also introduced `protected_qty = current_qty if current_qty > 0 else session_qty` to correctly size protection for the full position when managing pre-existing holdings under Option C.

### 3. xAI 500 errors on chat/completions endpoint
**Problem:** Pass B (reasoning step) was using `client.chat.completions.create()` which returned HTTP 500 errors from xAI's API.
**Fix:** Switched both Pass A and Pass B to use `client.responses.create()` (the responses API), which works reliably with Grok.

### 4. ADBE order rejected — insufficient settled cash (Error 201)
**Problem:** Bot saw ~$1,576 TotalCashValue and tried to buy ADBE, but IBKR rejected the order. Root cause: user had sold AAPL earlier that day, so ~$1,380 of cash was unsettled (T+1 rule — cash account proceeds not available until next business day).
**Fix:** Changed `get_available_cash()` to read `SettledCash` tag instead of `TotalCashValue`. Bot now only spends cash that is actually available to trade with.

### 5. Bot not tracking deployed capital
**Problem:** Bot had $1,500 portfolio cap but after deploying ~$200 into NVDA, it still told Grok it had $1,500 free — leading to potential over-allocation attempts.
**Fix:** Added `cash_deployed` tracking in `RiskState`. `free_budget = investable - risk.cash_deployed` is now passed to Grok so it knows the actual available budget each cycle.

### 6. Grok allocating tiny amounts (only 1 share despite ~$1,500 budget)
**Problem:** Bot was passing percentage-based allocation to Grok, which returned conservative percentages resulting in 1-share orders.
**Fix:** Switched to USD-based allocation. Grok is now told the exact dollar budget and returns `usd_allocation: {"NVDA": 500}` style responses. Bot converts USD → qty at the current price.

## Token Cost Note
xAI web search (Grok with live X/web search tools) costs ~$5 per 1,000 queries. Prompts were compressed ~65-70% to reduce token spend. Bot also skips Grok scan entirely when free budget < $150 (not enough to buy anything meaningful).
